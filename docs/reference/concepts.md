# 核心概念

本文档面向想理解工具工作原理的科研用户，解释：为什么本项目从 GROMACS tpr 拓扑直接读取力场原子类型来鉴定化学基团，而非像 PLIP/ProLIF 那样从坐标重建化学信息。

## 问题背景：为什么现有工具对 MD 轨迹不可靠

分析 MD 轨迹中的分子间相互作用时，主流工具（PLIP、ProLIF）的工作方式是：从轨迹帧的原子坐标出发，**重建**分子结构，再推断化学基团。

例如 PLIP 使用 OpenBabel、ProLIF 使用 RDKit，它们做三件事：
1. **重建键序**：根据原子距离判断原子间是单键、双键还是芳香键
2. **推断芳香性**：判断某个环是否为芳香环
3. **重新加氢**：如果结构缺少氢原子，按化学规则补上

这套流程的缺陷：
- 对 MD 轨迹，坐标含热涨落，距离判断键序不准确
- 对 trjconv 导出的 PDB（无 CONECT/键序记录），OpenBabel 无法重建键合关系，芳香环判定直接失败（实证：PLIP 对 D927 结构判 `num_aromatic_rings=0`、π-π 堆积全丢）
- 每帧重复推断，计算量大且结果随帧波动
- 推断结果与模拟实际使用的力场参数**不自洽**

## 核心创新：直接读取 tpr 力场原子类型

本项目不重建化学，而是直接读取 GROMACS 拓扑（tpr）中**已经参数化好的力场原子类型**。

### 为什么可行

力场原子类型（如 GAFF 的 `ca`、`na`、`nb`；Amber 蛋白的 `CA`、`N3`、`CX`）不是任意标签，而是参数化时由 antechamber/sobtop 依据分子电子结构做出的**化学判决的留存记录**：

| 类型 | 化学含义 |
|:-----|:---------|
| `ca` | 芳香碳 |
| `na` | 吡咯型芳香氮（带 H） |
| `nb` | 吡啶型芳香氮（不带 H） |
| `os` | 醚氧（单键） |
| `C` | 羰基碳 / 芳环碳（双身份） |
| `N3` | 蛋白正电氨基 |

这些类型名**本身就编码了杂化状态、芳香性、极性、是否带氢等化学特征**。因此直接读取类型 → 判定基团，是零损失、零歧义的。

### 信息论视角

- **重建**（PLIP/ProLIF）：从"连接性 + 几何"反推化学判决 = 丢弃已编码的信息 + 注入推断噪声
- **直接读取**（本项目）：读取参数化时已存留的判决 = 零损失、零歧义

### 结构上的系统性优势

全原子力场（Amber 系）中，以下化学信息**全部显式存在**，零推断、100% 确定：
- **H 键供体**：供体原子 D 与氢 H 之间的键条目显式存在，且 H 带正电荷
- **水桥**：水分子由残基名 SOL/HOH 标识，氧原子 OW、氢原子 HW 明确
- **金属配位**：金属中心由元素（如 Mg）+ 电荷标识

这是 PLIP（需重新加氢）/ProLIF（需推断键序）结构上无法做到的。

## 两段式架构

工具将分析分为两段，第一段只做一次、与帧无关：

```
① 基团鉴定（难点）
   tpr 力场参数（原子类型 + 键合图 + 显式 H + 电荷）
   → 确定性识别能参与相互作用的化学基团（芳香环、H 键供受体、带电基团…）
   —— 只做一次，与帧无关

② 几何判定（成熟件）
   基团带标签后，逐帧用 PLIP 式距离/角度/平面临近判据
   → 每帧相互作用列表 → 时间统计
```

- **基团鉴定**只依赖拓扑，不依赖坐标，因此跨帧一致、可复现
- **几何判定**复用成熟的 PLIP 判据，聚焦于相互作用检测本身

## 差异化定位

与竞争工具相比（MDLR、MD-IFP、ProLIF），本项目是**唯一读取 GAFF/Amber 类型语义做化学判定**的工具。ProLIF 的 CHANGELOG 有 20+ 条 SMARTS 修补记录，自证"MD 简单推断易错"。

**卖点叙事**：本项目卖"**确定性 + 与模拟力场自洽**"，而非"更准"——对标准药物分子 RDKit 推断往往也准，硬碰正确率是脆弱卖点；但"基团鉴定只做一次、结果与帧无关、与力场同源"是竞争工具结构上无法做到的。

## 支持边界

- **力场范围**：首版支持 Amber 家族（amber03/94/96/99/99sb/99sb-ildn/GS/14sb + GAFF/GAFF2），类型映射已验证零冲突
- **全原子力场**：本工具依赖显式氢原子；对联合原子力场（如 GROMOS，无显式 H）供体鉴定失效，声明不支持或降级
- **键序缺失鲁棒**：即使 tpr 不保留键序（全 func=1），芳香性判定仍可靠——因为类型名已编码芳香性，键序只是第二重交叉证据
